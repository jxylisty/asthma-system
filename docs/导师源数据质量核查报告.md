## 二、严重问题

### 问题 1：理化性质表 957 行整体右移一列 🔴

**文件**：`化合物理化性质和生物利用度属性-赵玉男.xlsx`

**证据**：2,499 行中有 957 行（38%）的 `LogS` 列填的是**分子式字符串**而非数值：

| 化合物 | LogS 列 | LogD 列 | LogP 列 |
|---|---|---|---|
| 10-Hydroxymajoroside | `C17H24O11` | 404.37 | 28 |
| 10-hydroxypaeoniflorin | `C24H30O12` | 510.49 | 36 |
| 11-Oxomogroside V | （分子式） | — | 89 |

**验证**：
- 这 957 行的 `LogD` 列值 **100%（957/957）等于该分子由 RDKit 算出的分子量**
- 这 957 行的 `LogP` 列值 **100%（957/957）等于该分子的重原子数**

即整行数据向右错位了一列。真实对应关系应是：

```
错位后：  LogS=分子式  LogD=分子量  LogP=重原子数
正确应为：LogS=?       LogD=?       LogP=?
```

**影响**：这 957 个化合物的 LogS、LogD、LogP、Pgp、F(20%)、Caco-2、MDCK 全部不可用。

**这个错误污染了入血预测模型**。核查发现 `pu_blood_prediction_v2.py:110` 直接读取这张表，其中 `pd.to_numeric(errors='coerce')` 只能把 LogS 列的分子式转成 NaN，而错位后填在 LogD / LogP / Pgp-inhibitor / F(20%) / Caco-2 / MDCK 这 6 列的**错误数值会被当作有效特征**：

| 特征 | 错位行均值 | 正常行均值 | 偏离 |
|---|---|---|---|
| LogD | 399.12 | 2.27 | 176 倍 |
| LogP | 28.29 | 2.70 | 10 倍 |
| F(20%) | 7.13 | 0.377 | 19 倍 |
| Caco-2 | 103.91 | −5.24 | 符号都反了 |
| MDCK | 112.92 | 0.000 | — |

**已完成的修复**（`scripts/rebuild_physchem.py`）：

1. 用 RDKit 重算 12 个可从结构精确得到的描述符（LogP/TPSA/HBA/HBD/RotB/Rings/MaxRing/nHet/fChar/nRig/Flex/nStereo）
2. 7 个 ADME 列（LogS/LogD/Pgp/F20%/Caco-2/MDCK）置空，交给模型的中位数填补
3. 保留原文件的双行表头与 29 列结构，新增第 30 列 `_data_quality_note` 标注每行来源

重算后的分布与原正常行高度吻合，验证了重算的可靠性：

| 描述符 | 重算 957 行均值 | 原正常 1,480 行均值 |
|---|---|---|
| TPSA | 112.33 | 108.18 |
| Num. H-bond acceptors | 6.89 | 6.78 |
| Num. Rings | 3.49 | 3.31 |

**模型已重训**：

| 模型 | 指标 | 修复前 | 修复后 |
|---|---|---|---|
| ccTCM V2（仅复方标签） | ROC-AUC | 0.9065 | 0.9031 |
| | PR-AUC | 0.5855 | 0.5731 |
| ccTCM 正式版（并集标签） | test ROC-AUC | 0.8073 | **0.8129** |
| | test PR-AUC | 0.7003 | **0.7025** |
| | test F1（阈值 0.47） | 0.6414 | **0.6546** |
| lite 部署版 | ROC-AUC | — | 0.8246 |

正式版指标**全面小幅提升**，说明清理错误特征后模型泛化更好。库内 569 个成分的入血概率已用新模型重算（`scripts/repredict_probabilities.py`），平均绝对变化 0.063，59 个成分变化超过 0.2。

**建议向导师确认**：这 957 行原本的 LogS/LogD/LogP 值是否有备份？如果导师手上有原始计算输出，可以补回（目前这些列是空的，靠中位数填补）。

### 问题 2：靶点表同一符号跨多个物种 🟡

**文件**：`靶点数据.xlsx`

**证据**：9,755 行数据，但只有 7,481 个唯一靶点符号。同一符号在不同物种下被重复记录：

| 靶点 | 记录数 | 物种 |
|---|---|---|
| TNF | 7 | 大鼠、小鼠、人、豚鼠、兔、牛、无物种 |
| IL6 | 5 | 小鼠、大鼠、人、无物种、牛 |
| ABCB11 | 4 | 小鼠、人、大鼠、人(NPASS) |
| TP53 | 4 | 人、大鼠、斑马鱼、人(NPASS) |

**影响**：`化合物作用靶点.xlsx` 里的 7,398 个靶点名，有 **1,418 个（19%）**在靶点表中对应多个物种。数据库 `target` 表以 `gene` 作主键，导入时每个符号只保留一条记录，物种信息丢失；`rel_compound_target` 又按基因名 JOIN，导致物种错配。

**实际影响有限**：因为 GSEA 富集分析只接受人类基因符号，我在重算三维评分时已显式过滤 `species='Homo sapiens' AND target_type IN ('Protein','Individual Protein')`。

**建议**：如需精确物种对应，应在 `target` 表增加 `species` 联合主键，或在使用处显式过滤物种。

### 问题 3：性味归经分隔符不统一 🟡

**文件**：`所有中药药材数据.xlsx`

**证据**：
- 「味」列 45 种取值，混用顿号和逗号：`辛、苦`（3 条）vs `甘,辛`（4 条）
- 「归经」列 92 种取值，同样混用：`肺,肝,肾`（2 条）vs `肝、脾、肾`（1 条）

**影响**：任何按 `、` 拆分归经做统计的代码都会漏掉用逗号的那部分。

**修复建议**：统一为顿号（中药学规范写法）。这是 5 分钟的事，但需要动源文件，建议先问导师。

## 三、中等与轻微问题

### 化合物主表：3 组重名 + 8 条无 SMILES + CAS 全空

**文件**：`化合物数据_cctcm2.0.xlsx`

| 问题 | 详情 |
|---|---|
| 3 组重名 | 欧前胡素（ccMon00000868/869）、异绿原酸A（896/897）、异欧前胡素（904/905），SMILES 完全相同 |
| 8 条无 SMILES | 党参吡咯烷鎓B、结合胆红素、共价胆红素、桉叶醇、小茴香烯、氧化铁及氧化锰、防风灵、白色线状环脂肽 |
| CAS 号 | **0/1,499 全部缺失**（但 PubChem CID 有 95%，可替代） |

其中「氧化铁及氧化锰」不是单一化合物，是混合物，本就不该出现在化合物表。

**SMILES 质量很好**：1,491/1,499 可被 RDKit 解析，且 **1,484/1,499 的分子量与 SMILES 自洽**（误差 <0.5），仅 7 条有偏差（多为水合物写法差异）。

### 血中移行成分标识表：只有正样本

**文件**：`化合物血中移行成分标识-赵玉男.xlsx`

2,485 行中 Yes=714、空值=1,771，**没有一条 No**。这意味着该表是"已知入血成分清单"，而非"全部成分的入血标注"。

**影响**：用它训练模型会产生选择偏倚——模型只在正样本上学，缺少可靠负样本。这正是 `项目概述` 里说的"正例未标注学习（PU Learning）"方法的由来，属方法层面的合理选择，但宣传时不应把它当作"有监督分类的准确率"。

### 药材-化合物-含量表：835 条重复（正常）

**文件**：`药材-化合物-含量-赵玉男.xlsx`

835 组 (药材, 成分) 重复出现，其中 834 组的**分类字段完全相同、只有含量值不同**：

```
('肉桂', '2-羟基桂皮醛'):
   含量 0.002~0.067%
   含量 0.005~0.077%
```

这是**不同文献/不同产地的多次测定结果**，是正常的数据聚合现象，不是错误。

**但要注意**：如果导入数据库时按 (药材, 成分) 去重，会丢失含量区间信息。当前数据库的 `rel_herb_compound` 就是去重后的（1,504 条），原始 6,191 行的含量数据没有入库。

## 四、源数据中值得表扬的部分

### 中药复方血中移行成分数据集.xlsx 是核心资产 🟢

这是 8 个文件里质量最高的一个，1,390 条记录包含完整的 **方剂 → 药材 → 入血成分 → PubChem CID** 链条：

- 46 首复方（与数据库完全一致）

- CID 缺失仅 576 条，且 **282/283 个 CID 能在血中移行标识表中找到**

**建议**：这个文件应该作为方剂分析的主数据源，而不是从 `prescription.description` 反推。

### 靶点数据与化合物作用靶点高度自洽 🟢

`化合物作用靶点.xlsx` 的 40,634 行与数据库 `rel_compound_target` **逐行 100% 对应**，无内部矛盾。物种分布合理（人类 24,476 / 小鼠 6,008 / 大鼠 4,284）。

### 药材表字段完整度高 🟢

273 味药材无重复，性、味、归经、药用部位、植物科属等字段填充率 97%+。

## 五、与数据库的关系：错误是导入时产生的

关键结论：**源数据质量整体高于数据库**。

| 数据项 | 源表 | 数据库（修复前） | 结论 |
|---|---|---|---|
| 化合物分子量 | 1,484/1,499 与 SMILES 自洽 | 0/569 与 SMILES 自洽 | 导入时破坏 |
| 药材-成分归属 | 6,191 行真实记录 | 1,657 条 99.2% 错误 | 导入时随机生成 |
| 方剂组成 | 46 首完整 | 274 条含 28 条合并串 | 导入时混入成分归属数据 |
| 三维评分 | **源表无此数据** | 569 组随机整数 | 无中生有 |

所以你之前说"他给数据一段时间给一点，我处理也麻烦"——确实如此，但**大部分错误不是源数据造成的，而是中途导入脚本的问题**。

## 六、建议向导师确认的 4 件事

1. **理化表那 957 行错位数据**：原始 LogS/LogD/LogP 是否有备份？这是唯一影响范围较大（38% 行）的源数据缺陷。
2. **甘草成分含白芍苷/芍药苷/苯甲酰芍药苷**：`药材-化合物-含量` 表里，甘草被关联了 3 个白芍成分（行 4842、4869、5448）。是录入错误还是确实有文献依据？

4. **血中移行标识表是否需要负样本**：当前只有 Yes，若要评估模型真实性能，需要补充"已测定但未入血"的成分。

## 七、复现方法

```bash
cd 数据库溯源/主要展示数据均为cctcm2.0

# 1. 理化表错位检测
python -X utf8 -c "
import openpyxl
wb=openpyxl.load_workbook('化合物理化性质和生物利用度属性-赵玉男.xlsx', read_only=True, data_only=True)
rows=list(wb['理化性质和吸收属性'].iter_rows(min_row=3, values_only=True))
bad=[r for r in rows if isinstance(r[2],str)]
print('LogS 列为字符串的行:', len(bad), '/', len(rows))
"

# 2. 靶点跨物种检测
python -X utf8 -c "
import openpyxl, collections
wb=openpyxl.load_workbook('靶点数据.xlsx', read_only=True, data_only=True)
rows=[r for r in wb['Sheet1'].iter_rows(min_row=2, values_only=True) if r[1]]
by=collections.defaultdict(set)
for r in rows: by[str(r[1]).strip()].add(str(r[5]).strip())
print('符号总数:', len(by), '跨物种:', sum(1 for v in by.values() if len(v)>1))
"

# 3. 化合物分子量自洽性
python -X utf8 -c "
import openpyxl
from rdkit import Chem
from rdkit.Chem import Descriptors
wb=openpyxl.load_workbook('化合物数据_cctcm2.0.xlsx', read_only=True, data_only=True)
rows=[r for r in wb['Sheet1'].iter_rows(min_row=2, values_only=True) if r[0]]
ok=sum(1 for r in rows if r[7] and r[5] and Chem.MolFromSmiles(str(r[7])) and abs(Descriptors.MolWt(Chem.MolFromSmiles(str(r[7])))-float(r[5]))<0.5)
print('分子量自洽:', ok, '/', len(rows))
"
```
