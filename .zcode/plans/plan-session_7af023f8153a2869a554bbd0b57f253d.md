# 「食养有据」——药食同源食疗·茶饮有效成分分析平台 规划

## 一句话定位

把你大创系统的「方剂→药材→化合物→入血预测→靶点→通路→疗效雷达」整条管线，从"治哮喘的药"平移到"日常吃喝的食"：用户测体质/选场景 → 得到茶饮和食疗方推荐 → **每个方子都能点开一份"有效成分说明书"**（这杯茶里有哪些活性成分、入血概率多高、作用什么靶点、有什么参考证据）。

**差异化**：市面上所有养生 App 只给"配方 + 功效文案"，你给的是"配方 + 硏成分证据链"。学术对标是澳门科技大学 2025 年的 TCM-DS（药食同源食疗方推荐大模型，做的是推荐，你做的是**可解释分析**，正好错位互补，还能引成参考文献）。

## 产品功能（MVP 六个页面）

1. **首页**：场景入口（熬夜护眼/润喉护嗓/换季调理/助眠/消化/控糖轻养…）+ 今日推荐 + 呼吸健康专区
2. **体质测评**：中医体质量表 CCMQ 精简版（60 题或 33 题简化版，判定算法=学会标准公开的转化分公式）→ 生成体质档案（九型：平和/气虚/阳虚/阴虚/痰湿/湿热/血瘀/气郁/特禀）→ 按体质匹配方子
3. **方子库**：茶饮方 + 食疗方列表（按体质/场景/功效筛选），详情含配方克数、做法、适宜/禁忌、出处
4. **有效成分报告页（核心卖点）**：成分清单 → 高入血概率成分 top → 靶点网络图 → 三维疗效雷达 → AI 通俗解读（"这杯茶凭什么有用"），支持 PDF 分享
5. **自定义配方分析**：用户自己勾食材组方 → 实时跑入血预测+富集（复用现有 `/prescriptions/analyze` 管线）
6. **我的**：体质档案、收藏、打卡记录 + 免责声明

## 数据层设计（基于现有 `tables.py` 扩展）

- `herb` 表加 2 字段：`is_food_homology`（是否在卫健委 106 种目录）、`food_catalog_batch`
- 新表 `food`：普通食材（银耳/雪梨/莲藕等不在 herb 表的），含性味、功效、禁忌、营养素 JSON
- 新表 `recipe`：type(茶饮/药膳)、name、method、effect_tags/scenes/constitutions(JSON)、suitable/unsuitable、source 出处、reference
- 新表 `rel_recipe_material`：方-食材多对多，带克数
- 新表 `user_constitution`：体质测评结果存档
- 新表 `recipe_analysis`：**预生成**每个方子的分析结果（解决 Render 免费实例冷启动 + 手机端 Cytoscape 性能问题——用户访问秒开，只有自定义组方才实时计算）
- 后端新增 `routers/recipes.py`、`routers/constitution.py`，其余（auth/ai/search）直接复用

## 实施路线（约 10-11 周到上线）

- **第 0 周 · 对齐**：拿本规划跟老师确认定位/首批方子口径（建议：茶饮 40 方 + 药膳 30 方，来源以《中医食疗学》教材与药膳标准为主）；定名字（候选：食养有据 / 本草茶语 / 一盏本草）
- **第 1-3 周 · 数据底座**：106 种目录打标对齐现有 278 味 herb 表（预计命中率过半）→ 缺的用 TCMSP 补成分 → 人工整理方子 Excel（复用你"数据库溯源"Excel 的流程）→ 写脚本入库
- **第 4-5 周 · 后端**：新表 + recipes/constitution 路由 + 分析预生成脚本（剂量×含量→成分暴露量估计，正好补大创中期自述的"暴露量特征未融入"短板）
- **第 6-8 周 · 前端**：新 Vue3 项目（移动端优先、清新食养风替换现在的暗色科研风），六个页面 + 分享海报生成
- **第 9-10 周 · 上线运营**：Vercel+Render 部署、埋点（测评完成率/方子浏览/收藏）、免责声明；冷启动用户：校内社群 + 体质测试 H5 引流 + 小红书
- **持续**：第二个软著申请、结题材料与论文素材沉淀

## 风险与红线

- **合规**：全文不用"治疗/疗效"字样，用"调理参考"；页面固定免责声明"本内容为健康参考信息，不构成医疗建议，不用于诊断治疗"；体质自测标注参考性质
- **数据严谨性**：所有成分数据标注来源库与文献；暴露量估算注明"估计值"——这也是学术上的诚实加分项
- **性能**：预生成报告 + 移动端网络图降级为简化布局/静态图
- **边界**：与现有哮喘系统分仓库，互不污染；新项目独立成软著与论文点，不算大创重复成果
